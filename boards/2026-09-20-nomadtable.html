Nomadtable

前 Amazon 工程师 Jay Raavi 做的独行旅客约局 App：今晚在陌生城市找人吃饭，不是交友大盘，也不是约会软件。

可带走的不是「月入十四万」故事，而是极窄场景、本人即用户、短视频飞轮、早期就收费。公开数字当方向信号，不当财报。

有争议的规模数字

同一时期 users / downloads / MAU、MRR / ARR / run rate 混用；冲突处保留。

数字含义与来源
~$140K月经常性收入量级（约 2026-09 访谈口径）自报 / 转述
1.8–2M用户或下载，不同帖口径打架自报冲突
$8.99+Plus 周订起价（美区 App Store）商店可核
~18 个月约 2025-03 上线后冲到六位数月收入量级时间线自报

产品长什么样

Plans first, chat second。先看到或创建附近活动（吃饭、sightseeing、咖啡），再聊天成行；也有行程重叠进群、AI 场地建议。

  • 平台：iOS / Android / nomadtable.app · 约 4.7★ / 2.1 万评分（调研时点）
  • 栈：React Native + Firebase · 长期接近一人公司
  • 变现：免费 + Plus / Trip Pass（短周期对齐「一趟旅行」）

为什么成立

极窄、当场能完成。痛点是今晚出门，不是「交个朋友」。相对 Bumble BFF / Meetup，转化路径更短。

Founder 就是用户。想法来自独旅挫败；长居用户密度城市（Tallinn → Bangkok）自己用、自己拍内容。

内容即增长。自报数亿短视频曝光；本人先跑通再按效果雇创作者。社交难靠买量硬推。

早期就收费。旅行场景付费意愿相对清晰；上线前做过广告与访谈验证，多轮 MVP。

时间线

  1. 2024 夏Bergen 独旅起意，随后离职 Amazon
  2. ~2025-03正式上线；首日宣称三千以上注册（自报）
  3. 2025-06约三个月：7 万用户 / 1 万美元 MRR（自报）
  4. 2026-01约百万下载、首个十万美金以上月收入；人在 Bangkok
  5. 2026-07宣称两百万用户 / 两百万 ARR
  6. ~2026-09访谈口径约 180 万用户 / 14 万美元 MRR，与前期数字冲突

可复制与难复制

相对可复制

  • 窄场景 + 活动优先
  • 上线前广告 / 访谈验证
  • 短周期订阅对齐行为
  • 住在用户密度城市 dogfood

很难复制

  • 大厂履历的心理与财务安全垫
  • 会拍、会写、会招创作者的复合能力
  • 已形成的城市密度与时间窗口

风险

  • 被当约会 App：商店评论反复出现 hookup；ToS 与 women-only 是补丁不是根治
  • 一人扛百万用户：性能、客服、审核债会堆
  • 数字口径漂移：模仿者容易高估付费率、低估审核成本

对你可带走的

  1. 先找「地理可聚集、当场能完成」的痛点，而不是先找全球市场上限。
  2. 社交增长默认按内容系统设计，而不是按买量预算设计。
  3. 公开数字只当方向；自己做事用付费转化、次日留存、同城供需比。
